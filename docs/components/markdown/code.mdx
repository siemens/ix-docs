# Markdown view - Code

## Basic

Set the `markdown` property to the Markdown source. Place `ix-markdown` in the default slot of `ix-chat-ai-message` to show AI responses.

<MarkdownPlayground height="40rem" />

Fenced code is shown in a [code block](../code-block). The info string sets the language, and a name in square brackets sets the filename:

````md
```ts [check.ts]
export const limit = 6.5;
```
````

## Streaming

Set `streaming` while the Markdown source is still growing, e.g. while an LLM response arrives, and update `markdown` with the complete source received so far (not only the new chunk).

- Unfinished syntax at the end is repaired for display.
- Blocks that are followed by another block are not re-created, so their DOM, scroll position and focus are kept.
- Updates are rendered at most once per animation frame.
- When `streaming` turns `false`, the final Markdown source is rendered once more to reconcile the result.
- The host has `aria-busy="true"` while streaming.

Table actions are shown once the table is complete. Their labels can be localized with `i18nCopyTable` and `i18nDownloadTable`.

## Directives

Directives use the [generic directives syntax](https://talk.commonmark.org/t/generic-directives-plugins-syntax/444): one colon for inline (text) Directives, two colons for a block (leaf) Directive on its own line and three colons for a container Directive with Markdown content. The label goes in `[...]` and attributes in `{...}`.

| Directive                                     | Renders                                            | Attributes                  |
| :-------------------------------------------- | :------------------------------------------------- | :-------------------------- |
| `:button[Label]{action=retry}`                | [Button](../button)                                | `variant`, `icon`, `action` |
| `:pill[Label]{variant=success}`               | [Pill](../pill)                                    | `variant`, `icon`           |
| `:icon{name=info size=16 label=Information}`  | [Icon](../../icons/icon-library.mdx) (inline only) | `name`, `size`, `label`     |
| `:::callout{type=warning heading="Heads up"}` | [Message bar](../messagebar) (container only)      | `type`, `heading`           |

- **Actions:** When a button with an `action` attribute is clicked, `ix-markdown` emits `actionClick` with `{ name, attributes }`. `name` is the value of `action`, `attributes` contains `variant`, `icon` and `action`.
- **Callout types:** `info` (also `note`), `success` (also `tip`), `warning` (also `caution`), `danger` (shown as alarm) and `critical`. Unknown types fall back to `info`.
- **Icons:** Icons used in Directives must be [registered](../../icons/developing-with-icons.md#reference-icons-by-name) by the application. Icons without `label` are hidden from assistive technologies.
- **Unknown Directives:** Directives without a mapping show their content. Directives without label or content keep their source text, so prose like `Ask me:later` is not affected.

```md
Pump P-102 shows **elevated vibration**. :pill[Warning]{variant=warning}

:::callout{type=warning heading="Heads up"}
Vibration above 6.5 mm/s requires an inspection within 24 hours.
:::

:button[Create work order]{variant=primary action=create-order}
```

## Custom components

The `components` option maps Directive names or Markdown node types (e.g. `table`, or node types produced by plugins) to Custom components. Mappings for built-in node types and Directives replace the built-in rendering.

A mapping is either:

- **A custom element tag name**, e.g. `{ asset: 'app-asset' }`. The Directive attributes are set as element attributes (event handler attributes like `onclick` are ignored).
- **A factory** (`MarkdownComponentFactory`) that receives a `MarkdownComponentContext` and returns `{ element, update?, destroy? }`. `update` is called while the block is still changing during streaming, `destroy` when the block disappears or `ix-markdown` is removed.

The context provides `name`, `attributes`, `text` (label or plain text), `markdown` (inner Markdown source), `node` (read-only syntax node) and `emitAction(name, attributes?)`, which emits `actionClick`.

### Framework helpers

Each framework package provides `createMarkdownComponent` to use components of your framework as Custom components:

| Package               | Usage                                                                                                                                                                                                                                                                                                                    |
| :-------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@siemens/ix-angular` | `createMarkdownComponent(MyComponent)`. Call it in an injection context, e.g. a field initializer, so dependency injection keeps working. Context fields that match inputs of the component (`text`, `attributes`, `emitAction`, ...) are set as inputs and updated in place. Available for module and standalone usage. |
| `@siemens/ix-react`   | `createMarkdownComponent(MyComponent)`. The component receives the context as `ctx` prop. It's mounted in its own React root, so React context of the surrounding tree is not available.                                                                                                                                 |
| `@siemens/ix-vue`     | `createMarkdownComponent(MyComponent)`. The context fields are passed as props. Call it inside `setup()` (or pass the app context as second argument) so plugins, provide/inject, router and i18n keep working.                                                                                                          |

## Rendering options

The `options` property takes a plain object. Share one object between views and replace the object to apply changes.

- **`plugins`:** [remark](https://github.com/remarkjs/remark) plugins that run after the built-in setup (GitHub Flavored Markdown and Directives).
- **`components`:** Custom component mappings, see above.
- **`extensions`:** Bundles of `plugins` and `components` that add a capability, e.g. math. Own `components` win over extension components.
- **`highlight`:** Syntax highlighter for fenced code, see [code block](../code-block/code).

The related types (`MarkdownOptions`, `MarkdownComponentFactory`, `MarkdownComponentContext`, `MarkdownExtension`, `MarkdownAction`) are exported from `@siemens/ix`.

## Security

Rendering is safe by default, also for the output of plugins:

- Raw HTML is shown as text, only `<br>` becomes a line break.
- Links are limited to http(s), mailto and relative URLs and open in a new tab.
- Images are limited to http(s) URLs.
- Built-in Directives only pass their listed attributes, see [Directives](#directives).

Content is rendered on the client only.

## Styling

Adjust the density and look of a Markdown view with these CSS custom properties on `ix-markdown`. They default to iX theme tokens.

- **Text and spacing:** `--ix-markdown--color`, `--ix-markdown--font`, `--ix-markdown-block--gap`, `--ix-markdown-heading--margin-top`, `--ix-markdown-heading-1--font` to `--ix-markdown-heading-6--font`
- **Lists:** `--ix-markdown-list--padding-inline-start`, `--ix-markdown-list-item--gap`
- **Block quotes:** `--ix-markdown-blockquote--border-color`, `--ix-markdown-blockquote--border-width`, `--ix-markdown-blockquote--color`, `--ix-markdown-blockquote--padding-inline-start`
- **Links:** `--ix-markdown-link--color`, `--ix-markdown-link--color--hover`, `--ix-markdown-link--color--active`, `--ix-markdown-link--outline-color--focus`, `--ix-markdown-link--outline-width--focus`
- **Code:** `--ix-markdown-code--font`, `--ix-markdown-code--background-color`, `--ix-markdown-code--border-color`, `--ix-markdown-code--border-radius`, `--ix-markdown-code--border-width`, `--ix-markdown-inline-code--padding-x`, `--ix-markdown-code-block--padding`
- **Tables:** `--ix-markdown-table--font`, `--ix-markdown-table--border-color`, `--ix-markdown-table--border-width`, `--ix-markdown-table-cell--padding`, `--ix-markdown-table-header--font`, `--ix-markdown-table-header--color`, `--ix-markdown-table-header--background-color`, `--ix-markdown-table-actions--gap`

```css
ix-markdown {
  --ix-markdown-block--gap: 0.5rem;
  --ix-markdown-table-cell--padding: 0.25rem 0.5rem;
}
```
